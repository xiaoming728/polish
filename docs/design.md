# Polish 设计方案与研发计划

个人用的 macOS 菜单栏应用：按全局快捷键，读取当前选中的文字（终端里读取输入框草稿），交给大模型润色，确认后安全地写回原处。

本文汇总 [Wayfinder 地图](https://github.com/xiaoming728/polish/issues/1) 上的全部决策，是 0.0.1 的实施规格。各项决策的依据都在对应工单里，这里只给结论。

## 1. 最小可用版本（0.0.1）的功能与边界

**包含**
- 菜单栏常驻（无 Dock 图标），全局快捷键默认 ⌥P，可以录制修改。
- GUI 应用：读选区 → 流式润色 → 按回填方式（预览 / 自动替换 / 小提示确认）写回。
- 终端（Terminal.app、Ghostty、iTerm2）：发送 Ctrl+G，由 `polish-edit` 接管整段草稿 → 润色 → 写回输入框，不自动执行或发送。zsh、Claude Code、Codex 均可用。
  - 2026-10-14 用户要求支持所有终端 Agent：不再按程序设 alias，改为在 zsh 中全局导出 `VISUAL`/`EDITOR`=polish-edit，原编辑器存入 `POLISH_FALLBACK_EDITOR`（未待命时转交它，且跳过指向自己的值）。各家唤起外部编辑器的按键不同，做成设置项：Ctrl+G（zsh、Claude Code、Codex）/ Ctrl+X Ctrl+E（zsh、Claude Code、Aider）/ Ctrl+X（Gemini CLI、Qwen Code）/ Ctrl+X E（OpenCode）。识别的终端扩展到 kitty、WezTerm、Alacritty、Warp、Hyper、Tabby、Rio（均未实测）。
- 多套配置（服务商 + Base URL + 模型 + 润色指令 + 额外请求体 JSON），API Key 存在本地文件（见第 6 节）。
- 默认带 6 个场景（⌘1–6）：默认润色、精简、结构化、仅纠错、译成英文、译成中文。不收「扩写 / 补充细节」，因为会凭空添加需求。老用户首次升级时补齐一次，沿用第一套配置的服务连接。
- 两种协议：OpenAI 兼容（Chat Completions）、Anthropic Messages。附带常见厂商预设。
- 设置界面：配置、通用、终端集成、使用统计、权限与隐私。
- 输入时中英提示（2026-10-13 新增，默认开启，可在菜单关闭）：中文输入法下敲拼音时，在光标上方显示「⌥1 英文（默认）/ ⌥2 中文」。按键后撤销刚敲的拼音键，再粘贴所选内容。
- 使用统计（2026-10-14 新增，无开关）：用来做功能取舍。记录每次润色的结局（替换 / 复制 / 放弃 / 失焦 / 失败 / 校验失败）按「配置名、应用 bundle id、来源（GUI / 终端 / 仅复制）」计数，输入提示的出现次数与 ⌥1 / ⌥2 选中次数，以及首字耗时、总耗时、提示耗时的 100ms 分档直方图。存在 `~/Library/Application Support/Polish/usage/YYYY-MM-DD.json`（目录 0700、文件 0600，本地时区按天分文件），不联网，**不含任何正文、拼音或译文**。设置里单独的「使用统计」标签页按时间范围汇总显示，可打开文件夹或清空。
  - 取舍：只存每天的汇总，**不保存逐条原始记录**。汇总足以回答采纳率、失败集中在哪些应用、耗时中位数等问题；逐条记录会积累出可还原使用时间线的明细，也让文件随使用无限增长。代价是以后想加新维度（如按小时）时，旧数据无法重算。中位数由直方图估算，精度为 100ms，4.9s 以上并为一档。

**输入时中英提示的实现**
- 用 session 级**主动** CGEvent tap（独立线程）识别按键：有未上屏拼音时，上屏键（空格、数字、标点、回车等）先拦住、读完输入法候选窗再放行（最多约 80ms），彻底消除「候选窗先收起导致漏读」的竞态；其余按键立即放行，处理异步回主线程。只在当前输入源是中文输入法（非键盘布局）时，累积 a–z 和 `'`。遇到空格、回车、数字、标点、方向键、修饰键组合、鼠标点击或切换应用时清空。
- 停顿 0.25 秒且至少 2 个字母时：
  - 先读输入法候选窗（输入法进程的 AX 树，超时 0.1s）的**第一候选**作为中文，⌥2 立即可用；
  - 英文先查 macOS 本地「牛津英汉汉英词典」（DictionaryServices，按 shortName 选定该词典，否则默认先命中汉语词典；单词 1–2ms，离线、不需要 Key），取第一义项的英文；短语、未收录或没装词典时再请求模型翻译这个候选词（设置里可关闭词典）；
  - 读不到候选时，退回「拼音 → `{"en","zh"}`」。
  - 期间再敲键，旧结果作废。
- **提速**（消融实测，deepseek-flash，热连接 7 次取中位数，交错测量）：
  - 输入提示：英文 761ms → 592ms，中文 0ms（直接取候选词）。
  - ⌥P 润色：首字 1142ms → 718ms，总耗时 1359ms → 924ms。
  - 收益主要来自**关闭思考**：只对已知服务发送方言参数（DeepSeek `thinking.type=disabled`、百炼 `enable_thinking=false`），用户可用「额外请求体 JSON」重新打开。
  - 输入提示另外加 `max_tokens 60`、`temperature 0`。注意：推理模型开着思考时，`max_tokens` 会被思考耗尽、正文为空，所以只对能关闭思考的服务（及 Anthropic）限长。
- 提示框不接收鼠标、不抢焦点。⌥1 / ⌥2 只在已出结果时临时注册为 Carbon 热键，提示消失即注销。按下后：组合态的拼音用 Esc 撤销（先确认候选窗还在，读不到候选窗就不替换），已上屏的本句按字数退格，再走剪贴板 + ⌘V。本 app 合成的按键带 `eventSourceUserData` 标记，事件监听会忽略。
- 2026-10-14 修复多删：原先按「敲了几个键就退几格」撤销拼音，输入法吞键或本句记录与实际不符时会删掉光标前的原有文字。现在能读到 AX 的应用先核对光标前文本以本句结尾（组合态拼音可在也可不在 value 中），Esc 后再核对一次；对不上就一个字都不删，结果写进剪贴板并提示「已复制，未替换」。读不到 AX 的应用（微信 4.x、终端）只能信本句记录（用户确认保留此行为）。
- 隐私：推翻了 grill 时「不监听输入」的决定。只在中文输入法下读取拼音键。Secure Input、AXSecureTextField 和终端中不工作（终端里可能在英文模式下敲 sudo 密码）。润色流程进行中时暂停。AX 调用超时 0.25s，避免拖住主线程。
- 残余风险：读不到 AX 的应用里，本句记录若与输入框不符（如漏记），仍可能多删；靠点鼠标、切应用、清空输入框时重置本句来兜底。

**不包含**：账号、云同步、历史记录、OCR、语音、插件系统、开机自启、Developer ID 签名与公证、Gemini 和 Azure 的专用协议、bash 下的回填（bash 中降级为复制）。

## 2. 实现路线比较

| 路线 | 优点 | 缺点 |
|---|---|---|
| **Swift 原生 + SwiftPM（采用）** | AX、CGEvent、Carbon 都是一手 API；体积小；不抢焦点的浮动面板容易做 | 本机没有 Xcode，只能用 CLT，测试框架不可用（用断言自检代替） |
| Electron / Tauri | UI 迭代快 | 系统 API 都要绕原生桥；常驻内存大；非激活浮动面板和焦点控制更难 |

不使用第三方依赖。快捷键自写 Carbon 实现，见「快捷键实现：修补 KeyboardShortcuts 还是自写 Carbon 热键」。

## 3. 用户流程与界面

**GUI**：选中文字 → ⌥P → 选区附近出现紧凑预览面板，流式显示结果 → ⏎ 替换 / ⌘C 复制 / Esc 放弃 / ⌘1–9 换配置重跑。润色进行中再按 ⌥P 即取消。流式输出时面板始终滚到最新一行。
- 面板或「⏎ 替换」提示失焦（用户点了别处）即隐藏，等同放弃（取消请求、原文不动），但不把光标放回——用户点的位置就是新光标（2026-10-14 用户要求）。
- 没有选中文字（2026-10-13 用户改为）：自动选中当前输入框里**光标前的全部内容**，再按选区流程处理；放弃或复制时把光标放回原处。AX 能读到输入框的值和光标位置时直接设置选区，否则只在焦点是文本控件、或应用完全不暴露 AX（如微信 4.x）时，用 ⇧⌘↑ 加 ⌘C 兜底。光标前也没有内容时，才提示「没有可润色的文字」。
- 回填前 ⌘C 重读不到选区时（微信等应用在面板拿走焦点后会清掉选区），⌘A 选回整个输入框再读；与原文逐字相同才替换。
- 自动替换模式：完成后直接回填；失败或校验不通过时弹出面板。
- 小提示确认模式：完成后出现「润色完成 · ⏎ 替换」胶囊，不展开全文。

**终端**：在输入框写好草稿 → ⌥P → 同样的预览面板 → ⏎ 写回输入框（不提交）。

**界面形态**（见「预览面板、小提示与设置界面的形态」）
- 预览面板：跟随光标的紧凑浮层，原文折叠。面板是非激活面板，不抢前台 App 的焦点。
- 小提示：光标旁的胶囊。
- 菜单：润色 / 取消、当前配置、回填方式、设置…、退出；未授权时顶部显示权限警告。
- 设置：五个标签页（「使用统计」为 2026-10-14 新增，其余与 UI 原型一致）。

## 4. 数据流程

```
⌥P ─┬─ 前台是终端 ─→ 发送设置里的按键，进入待命 1.5s；0.5s 没连上再发 Ctrl+G / Ctrl+X 中的另一个
    │                  ├─ polish-edit 发来草稿 ─→ 立即 CANCEL（原样放回，CLI 不挂起）─→ 润色 ─→ 预览
    │                  │     └─ 确认 ─→ 前台仍是原终端时用同一按键再握手 ─→ 草稿未变回 OK(结果)，变了回 CANCEL 并复制结果
    │                  └─ 超时 ─→ 降级：读取终端选区，只提供复制；提示可用 ZLE_LINE_ABORTED 恢复
    └─ 其他 App ─→ 读选区（AX 优先，⌘C 兜底）─→ 润色 ─→ 回填（校验 → ⌘V → 恢复剪贴板）
```

**读选区**
1. 取系统焦点元素的 `kAXSelectedTextAttribute`。
2. 读不到时，对该 App 设置一次 `AXEnhancedUserInterface`（Chromium）和 `AXManualAccessibility`（Electron）。设置后约有 2 秒防抖，所以本次直接走 ⌘C 兜底，下一次再用 AX。
3. ⌘C 兜底使用哨兵法：先往剪贴板写入随机哨兵，发送 ⌘C，最多等 300ms；剪贴板仍是哨兵就视为「没有选区」。完成后恢复原剪贴板。
4. 通过 ⌘C 读到的文本，在「自动替换」模式下也强制改为预览确认。

**模型请求**
- 系统提示 = 配置里的润色指令；用户消息 = `<text>\n原文\n</text>`。
- OpenAI 兼容：`POST {base}/chat/completions`，Bearer 鉴权，读取 `choices[0].delta.content`，以 `[DONE]` 结束，忽略 `:` 注释行和空块。
- Anthropic：`POST {base}/v1/messages`，带 `x-api-key` 和 `anthropic-version: 2023-06-01`，`max_tokens` 为 4096，读取 `content_block_delta` 中的 `text_delta`，以 `message_stop` 结束，收到 `error` 事件即报错。
- 额外请求体 JSON 按顶层键合并进请求体，覆盖默认值。
- 超时：首字 30s、总计 120s。不自动重试。
- 同一时间只允许一个请求。

**终端握手**（见「polish-edit 与 app 的通信和握手约定」）
- socket 位于 `~/Library/Application Support/Polish/edit.sock`，权限 0600。
- 帧格式：一行头部 + n 字节正文。
  - polish-edit → app：`EDIT n`。
  - app → polish-edit：`NO`，`CANCEL`，或 `OK n`。
- polish-edit 就是 app 二进制本身：`Contents/MacOS/polish-edit` 是指向主二进制的符号链接，按 argv[0] 分发。
- 连不上、或收到 `NO` 时交给原编辑器，查找顺序为 `POLISH_FALLBACK_EDITOR` → 非 polish-edit 的 `$VISUAL` → `$EDITOR` → `vi`。

## 5. 异常处理

| 情况 | 处理 |
|---|---|
| 焦点或选区在润色期间变了 | 回填前重新读取选区（用原来的读取方式），与原文逐字比对，并检查前台 pid 是否不变；不一致则不替换，面板显示原因，只保留 ⌘C |
| 剪贴板 | 读取和回填前保存所有条目，事后恢复；回填时写入的内容带 `org.nspasteboard.TransientType` 标记；恢复前若 changeCount 已被他人改动，则不恢复 |
| 并发 | 只有一个活动请求；进行中再按快捷键 = 取消；同一时间只有一个终端待命 |
| 请求失败或超时 | 原文不动；面板显示错误（含 HTTP 状态和服务端消息）；按快捷键可重试 |
| 投递按键时用户还按着 ⌥ | 用 privateState 事件源，并显式设置 flags |
| 终端 Ctrl+C、app 崩溃 | polish-edit 不改文件，exit 0；app 发现断开后取消请求、关闭面板 |

## 6. 权限、密钥与打包

- **权限**：辅助功能（AX 读取、CGEvent 投递）。首次启动时请求授权；未授权时菜单顶部显示警告。全局快捷键（Carbon）不需要权限。
- **密钥**：本地文件 `~/Library/Application Support/Polish/keys.json`（目录 0700、文件 0600，先写临时文件再原子改名），键为 `base:<Base URL>`，同一服务的场景共用一个 Key。**禁止使用钥匙串**（用户 2026-10-14 要求：无团队 ID 的签名下钥匙串每次升级都弹确认框）。ad-hoc 签名下不能用 data protection keychain。
- **其他设置**：配置、回填方式、快捷键存在 UserDefaults。
- **打包**：`scripts/build-app.sh`。步骤为 `swift build -c release` → 组装 `build/Polish.app`（Info.plist 含 `LSUIElement`）→ 创建 `polish-edit` 符号链接 → `codesign -s -` 做 ad-hoc 签名 → `codesign --verify --strict` 校验。
- **签名**：有本地证书「Polish Local Signing」（`scripts/make-signing-cert.sh`）时用它签名，身份为 bundle id + 证书，重建后辅助功能 / 输入监控授权不失效；否则 ad-hoc，重建后需重新授权。

## 7. 研发计划与验收

**阶段 1：PolishCore（纯逻辑，可自动验证）**
- 内容：SSE 解析、两种协议的请求构造与增量提取、额外 JSON 合并、厂商预设、握手帧编解码、原编辑器查找、快捷键显示名。
- 验收：`swift run core-checks` 全部通过。

**阶段 2：App 外壳**
- 内容：菜单栏、Carbon 快捷键与录制、设置界面、Key 与配置持久化。
- 验收：`scripts/build-app.sh` 成功，并通过 `codesign --verify --strict`；启动后菜单栏出现图标，设置能保存和读回。

**阶段 3：GUI 流程**
- 内容：AX 读取、⌘C 兜底、预览面板、小提示、三种回填方式、校验与剪贴板恢复。

**阶段 4：终端流程**
- 内容：Ctrl+G 投递、socket 服务端、polish-edit、降级。
- 验收：沿用握手原型的 pty 用例（zsh 端到端），改为调用真实的 `polish-edit`。
